# Recipient-observation receipts and independent retention planning

The unregistered adapter returns a canonical, metadata-only receipt for the exact
accepted handoff. A separate disposable review profile gates read-only retention
planning through two signed records. No route is installed and the service writes
no receipt, proposal, decision, document, journal or retained plan.

Trusted host wiring supplies the existing metadata service, separate review
profile, owner-only directory and identity pins, public verification keys, closed
receipt specifications, exact review-set hashes and server-held recipient scope.
Requests contain only opaque entry IDs and exact hashes. They cannot supply
paths, keys, principals, credentials, decisions or new trust bindings.

`observe` authenticates the assigned recipient reviewer before registry lookup or
file inspection. It freshly calls the complete predecessor acceptance service,
which performs two signed-source checks and two recipient observations. The new
wrapper checks its own stable metadata and bindings around that call. It does
not multiply the entire nested verification chain. The resulting receipt holds
only schema/purpose, opaque IDs, context and acceptance hashes, observation time,
expiry and false authority flags. It contains no document content, ciphertext,
filesystem paths, credentials, signing keys or actor/session snapshots.

An external operator or disposable fixture writer may exclusively retain a new
owner-only receipt and independently signed preparer/reviewer records. Their exact
hashes must be separately registered by trusted wiring. Retained bytes never
provision a pin or prove genuine receipt acknowledgement.

`plan` authenticates the independent reviewer before lookup, parsing or source
inspection. Both distinct keys/principals must match the separate review profile
and current context. Signatures bind exact receipt/proposal bytes, assigned roles,
current sessions, decision/reason and validity windows. Rejection or requested
changes withhold plans before source inspection. Accepted review requires fresh
predecessor acceptance and exact receipt applicability, with review-file reads
before and after verification. Changed files, namespaces, signatures, authority,
versions or context withhold the result and leave retained history untouched.

The directory is bounded to twelve files and each canonical file to 4 KiB.
Missing, linked, interrupted, oversized, malformed or unregistered entries remain
untouched. Admission has a combined two-second checked budget; operations retain
the ten-second checked budget. Expiry is capped by original evidence, the receipt,
current acceptance, signed review, keys and sessions. Reopening cannot renew it.

The returned plan is disposable metadata planning readiness. Genuine retention
permission, key custody, issuer/channel authenticity, durability, atomic snapshots,
recovery, trust renewal, activation and legal acceptance remain unqualified.
All corresponding authority flags stay false. Your pending legal review is not
changed by this engineering qualification.
