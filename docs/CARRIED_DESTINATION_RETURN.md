# Guarded carried-destination return reconciliation

Explicit return from a carried-arrival-preserving exact-event handoff can now
retain its currently verified destination separately. The original carried
arrival, every earlier receipt/queue/preparation and the current handoff's queue
and preparation remain unchanged. R03/R05 remain partial.

## Capture and storage

`private-carried-destination-return-v1` contains only recipe, the validated
CarriedArrivalEventHandoff and a reduced destination observation. It has fixed
schema/depth and retains no predecessor windows, source bodies, quotations,
review notes, matter titles or recursively appended prior returns.

Capture requires an explicit return with currently available matching metadata
and exact-event history. Check the purpose-bound selected target, original
intent, frozen evidence, every retained selected/same-known-head packet and
monotonic observation time/revision. Preserve exact customer OR, workspace date
field/range, source dates, bucket, matter/analysis/context, frozen version/manifest
and selected event/packet, including explicitly unknown historical identities.
Unknowns and pending admissions are not repaired, promoted or inferred.

Both unavailable inputs restore selection only. Loading, failed, denied, blocked
or retired views cannot reuse an older successful read. Partial, inconsistent
or redirected metadata fails closed without replay or an invented receipt.

Validate before allocation/eviction; clone input/output. One new entry holds the
new observation and separate unchanged earlier projections. Eight principal-local
memory entries, thirty-minute expiry, opaque tokens and no browser storage remain.
Reload, principal loss, expiry and eviction close the token.

## Fresh private reconciliation

Require explicit filter restoration and a fresh authorized bounded queue
containing the target, followed by its existing exact-event GET, before showing
retained destination details. Current explicit same-firm matter content grants
are mandatory; customer tags confer no permission. An omitted target remains
unobserved, with no retained details, fallback response, automatic next-window
scan or hidden retry.

Compare fresh head/version/revision independently against the new destination,
original carried arrival and all earlier destinations/preparations. Validate
exact filters, window, scope, frozen evidence and all immutable pins. Reject
regressive queue/event clocks or revisions. Different heads imply neither a
path, legal effect, approval nor replacement selection. Unknowns and pending
admissions remain explicit; separate timestamps are not an atomic view.

Commit all comparison panels together only after every check and while token,
scope, portfolio revision and request fence remain current. A new observation,
window/preparation, token/target, filter, principal/scope, expiry or navigation
retires prior views, links and replies. Denied or late data cannot reopen private
details or trigger another request.

carried-arrival preparation is withheld on these entries because its contract
cannot carry the additional destination. Existing separate source actions keep
their own authorization and evidence checks. Append-only review history remains.
No backend endpoint/schema, automatic source-body read, review/renewal/export
write, provider call, public graph update or deployment is introduced.
