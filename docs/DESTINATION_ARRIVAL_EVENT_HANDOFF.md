# Guarded destination-arrival-preserving exact-event handoff

An explicit handoff now carries the complete saved destination arrival through a
fresh preparation to the exact historical review event. Original customer/date
filters, frozen evidence and every earlier review observation remain unchanged.
This is private metadata navigation; R03/R05 and legal qualification remain partial.

## Preparation and purpose

`private-carried-destination-arrival-event-handoff-v1` has a fixed schema: the
complete validated `CarriedDestinationArrivalReturn`, one fresh containing queue
comparison, a reduced preparation and two observation timestamps. It cannot carry
another instance of itself, arbitrary history windows, source bodies or notes.

Require a live principal-local return token, exact filter/scope/revision match,
authorized containing queue and complete current context/selected/head admission.
The new action is separate from the older purpose, which remains withheld.

Exactly two fresh selected-event `window=1` metadata GETs must match the queued
identities, admissions and revision except observation timestamps. Verify the
current request fence before/after each read and before allocation. First failure,
denial, drift or retirement stops without retry, fallback or a second read.

Check exact customer OR IDs, workspace date field/range, source dates and bucket;
matter/analysis/context; frozen version/manifest; selected event/packet; and all
known retained same-ID head packets. Keep all clocks/revisions monotonic.
Unknown or pending current states cannot prepare; historical uncertainty remains
explicit and cannot convey current approval.

Validate before nonce allocation/eviction and clone stored/returned payloads.
The existing eight-entry, thirty-minute principal-local memory book and opaque
purpose tokens remain. Reload, expiry, eviction and principal loss close access.
No browser persistence or added sensitive URL payloads.

## Destination and explicit return

Validate purpose and exact target before the existing single fresh exact-event
metadata GET. Reject context-only, alternate-event, review and renewal redirects.
A different token for the same event remounts and revalidates the destination.

The destination compares new preparation, saved arrival and earlier observations
independently. Later head/version changes, unknowns and pending admissions are
shown without substituting the selected event, inventing a path or transferring
approval. Disclosure rows preserve all original versions and observations.
Metadata views do not open source passages, review forms, export or provider calls.

Explicit verified return restores the complete original saved arrival unchanged
without adding a GET or write. It does not capture this new destination. Failed,
denied, loading, blocked or retired metadata yields selection only; partial or
conflicting input fails closed. Current same-firm matter content grants remain
mandatory; customer tags never confer access. Private metadata stays outside
public legal graphs, exports and assistant prompts.

validates the complete saved history once. Its private operation-local checks
then validate every fresh identity and compare all 14 retained observations.
Queue and prepared metadata each pass independent strict schema/context checks,
with stable equality and separate monotonic clock checks. There is no verdict or
checker shared between public calls. Awaited preparation uses cloned filters,
history, queue and replies, preventing callback mutation of the original baseline.
