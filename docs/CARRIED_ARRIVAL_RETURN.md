# Guarded carried-arrival return reconciliation

Explicit return from an onward-return-preserving exact-event destination can now
retain its currently verified arrival separately. The original OnwardReturn and
every earlier receipt, arrival, queue and preparation remain unchanged. This is a
private review-navigation increment; R03/R05 remain partial.

## Capture and bounded storage

`private-carried-arrival-return-v1` has three fields: recipe, the existing
validated OnwardEventHandoff, and a reduced arrival observation. The latter holds
exact navigation metadata, selected-event metadata and current-head metadata.
It retains no predecessor windows, source text, quotations, review notes, matter
titles or arbitrary recursively appended return objects.

Capture occurs only on explicit return with currently available matching
metadata and exact-event history. Validate the purpose-bound target, original
intent, frozen evidence, chosen event and all known retained immutable identities.
Both inputs unavailable produce selection only; inconsistent or half-available
inputs and alternate-event/context-only/write-purpose redirection are rejected.
Loading, blocked, failed or retired views cannot reuse an older successful read.

Preserve exact customer OR, workspace date field/range, source-record dates,
bucket, matter/analysis/context, frozen version/manifest and selected event/packet,
including original unknown identities. Never select the current head implicitly,
rebase an original observation, invent an unobserved intermediate version or
transfer review approval.

The principal-bound memory book remains limited to eight entries and thirty
minutes. Validation precedes allocation and eviction. Clone inputs and outputs;
store separate unchanged onward/arrival/receipt projections for their existing
panels. An opaque token carries no private payload in the URL. Browser storage is
unused; reload, principal change, eviction and expiry close the token.

## Fresh authorized reconciliation

Hide retained carried-arrival details until explicit filter restoration and a
new bounded authorized queue containing the target, followed by its existing
exact-event GET. Customer tags confer no access. A target outside the window is
unobserved; no old-response fallback, automatic next-window scan or retry occurs.

Validate exact queue filters/window/scope, frozen evidence and event metadata.
Reject regressive queue/event timestamps or revisions and immutable selected or
same-known-head packet substitution against every retained observation. Compare
fresh head/version/revision with the carried arrival independently of original
onward destination, original arrival and all preparations. Different heads imply
neither a path nor legal effect or replacement selection. Unknown identities and
pending admissions remain explicit; separate timestamps are not an atomic view.

All comparisons commit together after every check and only while the token and
request fence remain current. New observation/window/preparation, target/token,
filters, portfolio revision, scope/principal, expiry and navigation retire prior
views/links/replies. A denied or retired response cannot reopen private details or
trigger a second request. No retained-detail fallback is used after denial.

[carried-arrival-preserving handoff](CARRIED_ARRIVAL_EVENT_HANDOFF.md) only with
fresh complete current identities. It contains no source forms or bodies.
The older onward-return preparation remains withheld on these entries because
it cannot carry the additional snapshot. Existing separate source actions retain
independent current authorization and evidence checks; append-only review
history is intact.

No backend endpoint/schema, automatic body/quotation retrieval, review/renewal/
export write, replay, repair, provider call or shared/public graph mutation is
added. Credentials, provider configuration and deployment are unchanged.
