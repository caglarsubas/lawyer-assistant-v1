# Guarded carried-destination-preserving exact-event handoff

A lawyer can explicitly prepare the exact selected historical review from a
fresh carried-destination queue comparison. The original destination, carried
arrival and all earlier receipts, queues and preparations remain unchanged.
R03/R05 remain partial; this is private metadata navigation.

## Purpose and preparation

`private-carried-destination-event-handoff-v1` carries one complete original
`CarriedDestinationReturn`, a reduced fresh queue comparison, a stable prepared
destination and two observation times. Its schema and depth are fixed. It
contains no source bodies, quotations, notes, matter titles, predecessor windows
or recursively appended handoffs.

The existing authorized bounded queue must contain the exact target and its
fresh exact-event metadata must be verified. Preparation additionally requires
known current head/version, available tools and complete context, selected-event
and head admissions. Historical unknowns or pending admissions stay as recorded.
Current explicit same-firm matter content grants remain mandatory; customer tags
do not confer permission.

Bind every original customer OR, workspace date field/range, source date range,
bucket, matter/analysis/context, frozen evidence version/manifest and selected
event/packet. Check every retained selected and same-known-head packet, clocks
and revisions. Preparation reads only the selected event, exactly twice, with
`window=1`; both must match the fresh queue and each other. Fences and active
token checks run before and after each awaited read. A failed, denied, drifting
or retired first read stops the second. No retry or fallback is added.

Validate before nonce allocation or eviction and clone input/output. Purpose
tokens share the existing eight-entry, thirty-minute, principal-local in-memory
book. Opaque URL tokens reveal no customer, evidence or review identity. Reload,
expiry, eviction and principal loss close access; no browser storage is added.

## Destination and return

Validate purpose and exact selected target before the destination GET. Alternate
events, context-only targets and review/renewal preparation redirects are denied.
A new token remounts the same event. The existing single fresh exact-event GET
compares the new preparation and retained destination independently while
checking every earlier immutable pin. A later head or version is an observation,
not a replacement selection, established path, legal effect or transferred
approval. Unknowns and pending admissions remain explicit.

A verified explicit return restores the original `CarriedDestinationReturn`
unchanged. This slice does not capture this new arrival. Unavailable, loading,
failed, denied, blocked or retired metadata yields selection only; partial or
conflicting metadata fails closed. Return performs no added GET or write.

Every filter/scope/revision, token/target, window or preparation change retires
panels, links and pending replies. New observations commit only while request,
scope and token fences remain current. Omitted queue targets disclose no retained
details and do not trigger automatic scanning.

The destination panel shows separate metadata observations with no automatic
source reads, forms, review/renewal/export writes, provider calls or public graph
updates. Existing source actions retain their own authorization. Review history
is append-only; private selections stay separate from shared legal graphs.
