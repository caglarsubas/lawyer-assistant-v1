# Guarded onward-return-preserving exact-event handoff

A lawyer can explicitly prepare the selected historical event from a freshly
reconciled onward-return queue. The retained onward destination, original arrival,
receipt, intervening queues and preparations remain separate and unchanged.
R03/R05 remain partial; this is a private review-navigation increment.

## Preparation and purpose

Offer **İleri dönüşü koruyarak tam karar geçişini doğrula** only when the target
occurs in the current authorized bounded queue and fresh exact-event metadata
passes onward-return reconciliation. Require known current version/head, complete
context/selected-event/head admissions and verified immutable identities. Omitted,
unknown, pending, denied or retired current observations withhold preparation.
Historical unknowns and pending admissions remain historical.

Use exactly two sequential GETs for the same pinned event with `window=1`.
Require stable frozen evidence, selected packet, current head packet,
version/revision, admissions and tools availability against the fresh queue.
Enforce monotonic timestamps and current fences before/after each read and before
allocating a purpose token. Stop on drift, denial or retirement without another
request, retry, pointer walk or inferred path.

`private-onward-return-event-handoff-v1` retains only:

- The original validated `OnwardReturn` unchanged.
- A separate fresh queue comparison against that retained destination.
- A preparation snapshot and its two observation timestamps.

This is a fixed-depth schema, not a wrapper accepting other purpose handoffs or
arbitrary recursive histories. No predecessor windows, source text, quotations,
comments or matter titles are retained. Customer OR, workspace date field/range,
source dates, bucket, matter/analysis/context, frozen version/manifest, selected
event/packet and original unknown baselines remain exact.

The separate **İleri dönüşü koruyan doğrulanmış tam kararı aç** link requires an
explicit click. Its token is purpose-bound to that exact event. Alternate event,
context-only and write-preparation redirects close before metadata reads. A new
token for the same event remounts and requires a fresh authorized observation;
alternative history links remain hidden on the purpose-bound destination.

## Destination and return

The existing exact-event metadata GET validates the selected event and every
known retained same-head identity. Reject packet substitution, changed frozen
evidence/scope and regressive time/revision. Compare fresh arrival with new
preparation and the retained onward destination separately; preserve the original
arrival and earlier snapshots in a disclosure. Changed heads establish neither a
path nor legal effect or replacement selection. Unknown identities and pending
admissions stay explicit; no approval transfers.

Verified explicit return restores the original **OnwardReturn unchanged**. This
arrival is not implicitly captured as an additional retained destination. A later
arrival-return reconciliation needs its own fixed-depth contract. Missing,
loading, blocked, failed or retired metadata returns selection only; one missing
half or inconsistent metadata is rejected. No receipt is invented, admission
repaired or write replayed. The returned queue requires fresh authorization and
filter restoration again.

The principal-bound in-memory book remains limited to eight entries and thirty
minutes. Payloads are cloned; validation precedes allocation/eviction. Opaque URL
tokens contain no private payload, and browser storage is unused. Reload, expiry,
eviction and principal changes close the token. Filters, revision, scope,
token/target, new preparation/observation and navigation retire views, links and
late replies; a retired first response cannot dispatch the second read.

All reads require current explicit matter-content grants. Customer tags and
administrator status grant no content access. Existing source tools retain their
separate explicit current checks. No automatic body read, form, review/renewal/
export write, provider request, backend endpoint/schema or public graph mutation
is added. Append-only independent review history, credentials and deployment
remain unchanged.
