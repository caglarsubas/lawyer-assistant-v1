# Guarded return to the portfolio source-review queue

From a portfolio source record, **Tam kaynak bağlamını aç** captures the exact
customer OR selection, workspace date field/range, separate source-record date
range and review bucket. The selected matter, analysis, immutable context,
frozen version/manifest hash and observed review-head ID are pinned separately.
Historical-event, predecessor, observed-head and current-context links carry the
same local return token. A new renewal context starts a separate selection.

**Portföy kaynak kuyruğuna dön** opens the source queue directly, with the captured
filter intent visible before any queue or target lookup. It does not reopen the
assignment list or restore old results, passages, comments, review forms or grants.
If a historical event was selected, its exact ID and observed packet hash remain
separate from the current head. An unavailable hash remains unknown.

## Session boundary and explicit observation

The return book lives only in the current principal's in-memory application session
and is supplied to the portfolio provider. Focus/visibility revalidation clears all
private views; the same verified principal can resume only intent, followed by fresh
preparation/observation. A different principal or failed session check discards it.
It contains at most eight intentions, with thirty-minute expiry and oldest-entry
eviction. It stores closed filter/identity/hash/time metadata, never client names,
source bodies, review notes, credentials or queue result arrays. The hash URL carries
one random token, not customer IDs or dates. Nothing is written to local/session
storage, cookies, public graphs or persistent cross-matter caches.

A copied token in another tab, reload, sign-out/principal change, expired token or
mixed context closes the return view. No filter guessing, default assignment view
or automatic broadening follows. Duplicate/malformed/mixed local-route parameters
also close the view before queue reads. A lawyer can explicitly prepare a separate
new source queue instead.

1. **Dönüş filtrelerini uygula ve hazırla** restores the exact customer/workspace
   filters to the left portfolio and refreshes its current authorized inventory.
   The source-record date range and bucket remain separately captured.
2. **Aynı filtrelerle yeni portföy gözlemi yap** requests a new authorized queue
   window, starting at zero. The server's echoed filters and closed metadata
   contract must match. Starting-window offsets and previous results are not saved.
3. Only when the selected context occurs in that returned window does the client
   request its exact context metadata, or exact selected historical-event lineage.
   These existing APIs independently enforce current firm and matter content grants.
   Customer tags, filters, hierarchy and administrative roles grant no content access.
4. The two observations must agree on matter/analysis/context, original frozen
   version/manifest hash, and currently observed review-head ID/state. A selected
   historical-event ID/hash must match too. Disagreement or failed authorization
   drops the entire partial queue and reconciliation; a fresh observation is explicit.

These are separate reads, not an atomic snapshot or a durable permission lease.
Their recording times are shown separately. A changed head or current analysis
version is reported while the old selected event and frozen evidence stay pinned.
Context/review admission, private-basis observation and source authorization remain
distinct. Missing or unverifiable bindings never become an approval.

If the selected record is absent, the result is **not observed in this bounded
window**. Absence does not prove deletion, access loss or complete portfolio coverage.
No hidden target probe or automatic pagination follows. The existing explicit next
window action remains bounded; totals and full-portfolio coverage stay unknown.
The lawyer can reopen a reconciled exact selection for a new metadata observation.

## Confidentiality and original evidence guards

Queue and identity observation invoke no source guard, passage/detail/export read,
inference, admission repair, review mutation, external request or shared graph update.
Public sources remain `not_checked`; legal readiness remains `not_established`.
Sensitive handoff views use the guide-only assistant and do not automatically expand
rich workspace documents. Source passages and reviewer notes still require the
original explicit source/retained-grant/private-version/reviewer/post-operation checks.
Historical metadata remains history rather than present authorization.

Customer/date/refresh, navigation, actor/session or expiry changes retire pending
requests and immediately hide protected results. Late responses cannot trigger a
new target lookup or restore previous buffers. Changing filters requires explicit
preparation again. An ambiguous mutation is never replayed, and independent review
history is never overwritten.
