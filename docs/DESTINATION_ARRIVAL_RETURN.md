Explicit return from the destination-preserving exact-event handoff now retains
its observed arrival separately. The original destination, carried arrival and
every earlier receipt, queue and preparation remain unchanged. R03/R05 remain
partial; this is private metadata navigation, not a legal-approval mechanism.

## Capture and storage

`private-carried-destination-arrival-return-v1` contains only recipe, the complete
validated `CarriedDestinationEventHandoff` and one reduced arrival observation.
Its schema/depth are fixed. No predecessor windows, source bodies, quotations,
review notes, matter titles or recursively appended returns are retained.

Capture reuses the currently verified exact-event GET on explicit return. Check
purpose/target, original customer OR, workspace date field/range, source dates,
bucket, matter/analysis/context, frozen version/manifest and selected packet.
Validate every known historical selected/same-head pin and monotonic clocks and
revisions. Unknown historical identities and pending admissions stay explicit.

Both unavailable metadata inputs yield selection only. Loading, failed, denied,
blocked or retired views cannot reuse an earlier successful response. Partial,
conflicting or redirected inputs fail closed without replay or an invented
arrival. Capture adds no request or server write.

Validate before nonce allocation or eviction; clone input/output. One row holds
the new arrival and unchanged earlier projections. The existing eight-entry,
thirty-minute, principal-local memory book, opaque tokens and no browser storage
remain. Reload, expiry, eviction and principal loss close access.

## Fresh authorized reconciliation

Require explicit exact filter restoration and a fresh authorized bounded queue.
Only a containing window triggers the existing exact-event metadata GET.
Current explicit same-firm matter content grants remain mandatory; customer tags
confer no permission. Omission exposes no retained details and causes no event
GET, automatic next-window scan, hidden retry or fallback.

Compare the retained arrival independently with fresh head/version/revision and
check every earlier destination/preparation. Reject substituted packets and
regressive clocks/revisions. Different heads establish neither a path, legal
effect, replacement selection nor approval. Unknowns and pending admissions
remain explicit. Queue/event disagreement clears all comparisons.

All panels commit together only under current token, scope/filter/revision and
request fences. New observation/window/preparation, token/target, expiry,
principal/scope changes retire views, links and pending replies. Denied or late
metadata cannot restore retained details.

The new panel is metadata only, with no forms or actions. The older
destination-preserving preparation is withheld because its contract cannot carry
the additional arrival. Separate source/review actions keep their own current
authorization. Review history is append-only; private matter metadata is not
promoted into shared legal graphs. No automatic body reads, review/renewal/export
writes, provider calls, public graph mutations or deployment changes are added.
