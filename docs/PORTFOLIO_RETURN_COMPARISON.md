# Selected and current review-head/version comparison

After [guarded portfolio return](GUARDED_PORTFOLIO_SOURCE_RETURN.md), explicit fresh
queue observation can show **Önceki ve yeni kimlikler** for the selected record.
The comparison keeps four identities separate:

- The original queue-observed review head and its observation time.
- The first verified context-observed current analysis version and its separate
  observation time. No version observation remains explicitly unknown; an observed
  but unavailable version is also unknown rather than an empty/current version.
- The fresh, separately authorized review head/current version observed on return.
- The selected historical review event and the unchanged frozen evidence context,
  version and manifest hash. Selected event and current head are never substituted.

The session-only intent recipe is now `private-portfolio-return-intent-v2`. The
closed record adds the historical head declaration and first version-observation
time. The first baseline remains immutable across current/head/event follow-up and
subsequent returns. A new explicit queue selection can start a different intent.
Existing bounded pool/expiry/principal isolation and opaque URL tokens remain;
nothing is persisted in browser storage or shared graphs. Reload still closes a
lost intent rather than converting it to guessed filters.

## Comparison and limits

A compact, labelled table shows original/fresh IDs, recording times and **same**,
**different** or **unknown** identity relationships. Unknown heads or versions never
mean no change. Verified absence of a recorded review remains different from an
unavailable review. Conflicting declarations on the same immutable head, mismatched
context/version/hash, mixed observation snapshots or a changed selected-event hash
close the comparison instead of silently reconciling it.

Frozen-versus-current version identity and selected-event-versus-current-head
identity are displayed separately. A different head does not prove lineage,
reversal, legal effect or loss of applicability. Head reachability stays unchecked.
Same IDs do not establish source permission, independent legal approval or current
private-basis suitability. Admission/private-basis states remain separate, and
source verification remains `not_checked` with legal readiness `not_established`.

The original bounded return protocol still applies: restore exact customer OR,
workspace date field/range, separate source-record date range and bucket; explicitly
observe a fresh queue window; only fetch exact target metadata if the selected
context occurs in that window. Two guarded reads are not an atomic snapshot. A
failed guard or disagreement drops all partial results. Window absence never
claims deletion, access loss or full coverage; no hidden probes/scans follow.

## Explicit follow-up

When the relevant identities/integrity are verified, local typed links can open:

- The exact selected historical event, without replacing it with the new head.
- The newly observed head as a separately chosen historical event.
- The same frozen context with a fresh current identity observation.

Links retain the original intent token/customer/date filters. Each destination
performs fresh firm/matter authorization and validates the original immutable
context/version/manifest hash before showing tools. Reopening the original selected
event also checks its captured packet hash. A structurally valid reply containing
substituted evidence or an altered selected-event packet closes before tools.
Pending/unavailable metadata does not gain approval; unknown event integrity
withholds its selected-event link. Explicitly selecting a different verified event
changes the navigation selection only, leaving recorded history and original
comparison baselines unchanged.

No link automatically reads source passages/notes, exports, starts inference,
renews evidence, repairs admission or submits independent review. Original
source/retained-grant/private-version/reviewer/post-operation checks still govern
actual inspection and export. Sensitive views remain guide-only with no automatic
rich workspace loading. Changed filters/refresh, actor/session, suspension,
navigation or expiry retire requests and immediately hide protected results.
