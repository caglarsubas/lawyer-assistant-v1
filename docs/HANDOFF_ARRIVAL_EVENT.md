Explicit preparation carries the complete saved handoff-arrival return through

## Dedicated fixed-depth purpose

`private-handoff-arrival-event-v1` contains exactly `recipe`, `observation` (the
complete `HandoffDestinationArrivalReturn`), an observed `queue`, a reduced
`prepared` identity and two `observed_at` timestamps. Recursive or arbitrary
purposes, predecessor windows, titles, notes and source bodies are not admitted.
Strict schemas also reject undefined extra keys.

Every public operation validates the complete original history afresh. Private
checks within that operation compare each new identity against all 20 retained
observations, including the separately saved arrival and heads known only to it.
The original matter/analysis/context, selected event/packet, frozen evidence
version/manifest, every known same-ID head packet and monotonic time/revision
remain bound. No checker or verdict survives a call. Baselines, awaited replies
and outputs are cloned.

Preparation requires exact original customer OR selection, workspace date field
and range, source-date range and bucket, restored explicitly, with a fresh
authorized containing bounded queue. Current head/version must be known and
context/selected/head admissions complete. Historical unknowns and pending
admissions remain explicit. Customer tags never grant access; active same-firm
explicit matter-content membership is still required.

Exactly two stable selected-event `window=1` metadata GETs follow. Principal,
token, scope, filters, revision and request fences apply before/after each await.
Failure of the first prevents the second; drift, substitution, denial or retirement
closes without retry, scan, fallback or a weaker purpose. The preceding handoff
remains withheld because it cannot carry the added arrival. No source, provider,
public graph or write request is added.

## Navigation, disclosure and original return

Validate purpose and exact selected event before the destination's existing
single fresh metadata GET. Other events, context-only targets and review/renewal
preparation redirects fail before reading. A new opaque token remounts the same
event and triggers fresh authorization/metadata checks.

Validation precedes nonce allocation/eviction. The dedicated purpose row cannot
masquerade as an earlier return or handoff. Inputs/getters/results are cloned;
eight principal-local entries, thirty-minute TTL, session/principal/reload/expiry
closure and no browser storage remain. Private metadata never enters public graphs
or assistant/provider prompts.

The metadata-only disclosure keeps all 20 retained observations, the new queue,
new preparation and fresh destination separate. New preparation and saved arrival
are compared independently with the destination; prior observations are not rebased.
Unknowns/pending admissions never become approval, readiness, a new head selection
or inferred path. Current token/principal/scope/filter/revision/request fences
protect state and clear derived results/links on failure, expiry or retirement.
Source and independent-review tools still require separate explicit opening and
current authorization checks.

Verified explicit return performs no request/write and restores only the complete
original `HandoffDestinationArrivalReturn` unchanged. It captures no further
arrival. Both unavailable inputs yield selection only; partial/conflicting inputs
or redirects fail closed. Failed/loading/blocked/retired views cannot replay an
earlier successful destination. Further arrival capture needs its own reviewed
contract and qualification.
