An explicit preparation carries the complete saved handoff-destination return
through exact-event navigation. Original customer/date filters, frozen evidence,
selected event and all earlier independent review observations stay unchanged.
Graph paths, current permission, legal readiness and approval are not inferred

## Dedicated fixed-depth purpose

`private-handoff-destination-event-v1` has exactly `recipe`, `observation` (the
complete `ArrivalHandoffDestinationReturn`), one observed `queue`, one reduced
`prepared` identity and two `observed_at` timestamps. It accepts no recursive
purpose, arbitrary predecessor window, title, note or source body. Undefined
extra keys fail strict schema validation too.

Each public operation validates complete retained history afresh. Private checks
within that operation compare every fresh identity against all 17 retained
observations, including heads known only to the separately saved destination
or earlier queues/preparations. They also check original matter/analysis/context,
frozen evidence version/manifest, selected event/packet, same-known-head packets
and monotonic timestamps/revisions. No checker or permission verdict survives
across calls. Every awaited reply and input baseline is cloned.

Preparation requires a newly authorized containing portfolio window, a known
current head/version and complete current context/selected/head admissions.
Historical unknowns and pending admissions remain explicit. The exact original
customer OR selection, workspace date field/range, source-date range and bucket
remain fixed. Customer tags grant no access; active same-firm explicit matter
content membership is still required.

Two stable selected-event `window=1` metadata reads follow, fenced before and
after each await. A failed first read stops the second. Drift, denial, retirement,
substitution or regression closes without retry, scan, fallback or a weaker
purpose. The preceding arrival-only preparation stays withheld. No source,
provider, graph or write request is introduced.

## Navigation and return

Validate purpose and exact target before the destination's existing single
fresh metadata GET. Other events, context-only targets and review/renewal
preparation redirects fail before any read. A new opaque token remounts even
when the exact event is unchanged. Validation precedes allocation/eviction;
inputs and outputs are cloned. The dedicated purpose row cannot masquerade as
an earlier return or handoff projection. Eight principal-local entries,
thirty-minute expiry, session/reload closure and no browser storage remain.

The metadata disclosure compares preparation, saved destination and original
history separately with the fresh arrival. Changed or unknown heads establish
no path, selection change, permission or approval. Pending admissions remain
pending. Current principal/token/scope/filter/revision/request fences protect
commits; failure or retirement clears the derived view. Source and review tools
still require their existing separate explicit opening and authorization checks.

Verified explicit return restores only the complete original saved destination
return unchanged. It makes no read or write and does not capture another arrival.
Both unavailable inputs yield selection only. Partial, conflicting or redirected
inputs fail closed; an earlier successful reply is not replayed. A later arrival
capture needs its own future contract and qualification.
