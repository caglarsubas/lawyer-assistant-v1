# Guarded comparison-to-renewal preparation

The [portfolio identity comparison](PORTFOLIO_RETURN_COMPARISON.md) now offers an
explicit renewal-preparation action when its current version, review head and
admission states are known. The original frozen context/version/manifest and
selected historical event remain selected; the observed renewal target is separate.

The closed `private-comparison-renewal-handoff-v1` attachment captures only bounded
matter/analysis/context identities, frozen hash/version, target version, head
identity/state and observation time. It shares the existing principal-scoped,
eight-entry, 30-minute in-memory return book. An opaque local route token carries
no client names, scenario, source text or review notes. Reload, expiry, suspension
or a principal change closes lost intent. Mixed, duplicate and malformed routes
close before tools; renewal preparation cannot also select a historical review.

## Explicit preparation and source selection

Arrival displays intent only. An explicit action restores exact customer OR,
workspace date field/range, separate source-record dates and review bucket. Fresh
identity verification reads original-context navigation metadata, renewal metadata
and navigation metadata again. The frozen version/hash, target current version,
review head/state, admission and analysis revision must agree. Archived or changed
records close preparation. These separate observations are not an atomic snapshot,
a source authorization or a durable permission lease.

Opening the renewal editor is another explicit action. It starts with blank new
selection inputs. The previous context contributes bounded source identities and
target digests, not old quotations, private comments or inherited approval.
Research-list lookup, original passage inspection, preview and freeze remain
explicit. The captured target and parent metadata are checked before and after
protected operations; existing server-side matter, source, retained-grant,
private-basis, independent-review and post-operation guards remain authoritative.

The preparation view contains renewal tools only. Ordinary historical inspection,
new review and export are reached separately under their original guards. New
research, explicit old-to-new passage mapping and a new independent review are
required for renewed work. There is no legal-equivalence or source-permission
inference from a matching identity.

## Separate successor and uncertain results

A confirmed freeze receipt retains the new context's exact version and manifest
hash. The original selection remains unchanged. An explicit, fresh authorized
metadata read can create a separate return intent for that distinct new context,
preserving all filters while establishing new comparison baselines. Old review IDs
and packet hashes are not copied. Opening it does not approve the new record.

When a write reports a context but its completion or post-operation check is
uncertain, the receipt stays pending. The preparation view offers no write replay.
Explicit successor observation can establish a separately selected record identity;
its parent renewal relationship remains explicitly unknown unless confirmed.
Observation neither completes pending admission nor repairs or authorizes effects.
An unknown network outcome without a record ID requires separate authorized
reconciliation; a saved request does not become permission to resend it.

Filter changes, refresh, actor/session changes, navigation, expiry, target drift
and failed guards retire delayed replies and clear protected forms, quotations and
partial results. The assistant remains guide-only. Private metadata stays outside
public graphs and browser persistence; no inference or external research starts
from this handoff.
